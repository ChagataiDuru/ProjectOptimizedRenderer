# AGENTS.md

This file provides guidance to Codex/AI agents working in this repository.

## Project overview

ProjectOptimizedRenderer is a C++20 Vulkan renderer. The project uses CMake presets and Conan 2 for dependency management. It is a renderer-first codebase, not a full engine/editor.

The core renderer should remain C++/Vulkan. A future Odin host/editor may be developed separately, but integration must stay behind a narrow C ABI with plain data structs and opaque handles.

## Documentation ownership and collaboration

Multiple agents may work in this repository at the same time.

- Do not revert or overwrite changes made by other agents.
- Before editing, check `git status --short` and inspect the files you intend to modify.
- If another agent changed a file, adapt to their work instead of restoring an older version.
- Documentation-only agents must not touch renderer source files under `src/`, `include/`, `shaders/`, `cmake/`, or build configuration unless explicitly assigned ownership.

## Exact debug workflow

Run commands from the repository root.

### Submodules

```bash
git submodule update --init --recursive
```

### Conan install

Use these exact debug install commands:

```bash
conan profile detect --force
conan install . --output-folder=build/conan-debug --build=missing -s build_type=Debug
```

### Configure

Use the platform debug preset. Each debug preset already points at the Conan-generated toolchain file under `build/conan-debug`.

macOS:

```bash
cmake --preset macos-debug
```

Windows:

```bash
cmake --preset win-debug
```

Linux:

```bash
cmake --preset linux-debug
```

### Build

macOS:

```bash
cmake --build --preset macos-debug --config Debug --parallel
```

Windows:

```bash
cmake --build --preset win-debug --config Debug --parallel
```

Linux:

```bash
cmake --build --preset linux-debug --config Debug --parallel
```

`debug` may remain as a macOS compatibility preset, but new documentation and automation should prefer `macos-debug`.

## Architecture guardrails

- Keep renderer behavior in C++/Vulkan.
- Do not introduce engine/editor concepts into the renderer core unless they are expressed as renderer-facing data or API boundaries.
- Do not replace the C++ renderer with Odin. Odin is only a possible future host/editor language outside this core.
- Keep any future cross-language boundary C ABI-friendly: plain data, explicit ownership, opaque handles, no C++ STL types across the boundary.
- Preserve Vulkan explicitness. Avoid hiding resource lifetime, synchronization, or ownership behind unclear abstractions.
- Prefer small, reviewable changes that keep rendering behavior measurable.

## Build and generated-file guardrails

- Do not commit build directories, generated binaries, screenshots, captures, logs, or compiled SPIR-V (`*.spv`) unless specifically requested.
- Treat `build/` as disposable local output.
- Shader sources live in `shaders/`; compiled SPIR-V is generated by the build and should stay out of version control.
- Large local assets may be absent from git. Do not assume a fresh checkout contains Sponza or other large binary test assets.

## Key technology stack

- Language: C++20
- Graphics API: Vulkan
- Windowing/input: SDL3
- Memory allocator: VulkanMemoryAllocator (VMA)
- Build system: CMake presets
- Package manager: Conan 2
- Shader tooling: glslang / SPIRV-Tools

## Directory guide

- `src/` — C++ implementation
- `include/` — C++ headers
- `shaders/` — GLSL shader sources
- `cmake/` — CMake helper modules/scripts
- `docs/analysis/` — Architecture and roadmap notes
- `docs/decisions/` — ADR-style decisions
- `docs/archive/` — Historical scratch notes
- `build/` — Local build output, ignored/disposable
